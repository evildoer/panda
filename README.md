# PANDAMIA Bot 🐼

> 💬 **Говорить по-русски!** — говорят, помогает.

Discord-бот для сервера PANDAMIA: модерация голосовых каналов (права владельцев, мут/глухота, тег 🔑), бан-таймаут за выход с сервера, музыка через `/play` (YouTube и др.) и мост между серверами (pipe).

**Стек:** Node.js 24 (портативный, в папке) + discord.js v14 + keyv/sqlite + @discordjs/voice + yt-dlp.

## Запуск

Один файл на всё — **`node.cmd`** в папке бота. Двойной клик по нему (или по ярлыку на него) — бот запускается, окно = живой лог. Из консоли — то же самое:

- `node .` — привычный запуск: в папке бота команда `node` берётся из `node.cmd` (совместимая версия из папки), поэтому работает и без ярлыка;
- `node.cmd` без аргументов — тот же запуск (окно остаётся живым после остановки);
- `node script.js аргументы` — обычный запуск любого скрипта на той же версии Node;
- Node ищется сам: портативный `node-v*-win-x64` в папке бота → системный из PATH;
- **Ctrl+C → Y** — бот остановлен, окно и консоль остаются (можно `git push` и другие дела);
- `node .` в той же консоли — запустить снова; `exit` (или крестик) — закрыть окно.

Системный node должен быть ≥ 18 (для музыки ≥ 22): если старый — `node.cmd` сам возьмёт портативный из папки, а вне папки бота продолжит работать системный `node`.

**Почему в папке бота версия Node фиксирована (не убирать `node.cmd`).** В `node_modules` лежат native-модули — `@discordjs/opus` (музыка) и `sqlite3` (бан-таймауты) — собранные под конкретный ABI Node. Портативный Node в папке — это ровно та версия, под которую всё установлено, и `node.cmd` гарантирует, что `node .` возьмёт её. Любая другая версия даёт `Cannot find module '@discordjs/opus'` и музыки не будет (rest поднимется, `/play` — нет). Смена версии = переустановка зависимостей тем же Node (`npm install`); портативный Node не в git — у нового развёртывания prebuild встанет под его собственную версию.

## Настройка (первый раз)

1. Скопировать `config.example.json` → `config.json`
2. Вписать свой `ID` (application id) и `TOKEN` (Bot → Reset Token)
3. Заполнить ID сервера/каналов/ролей (ПКМ по роли/каналу → «Копировать ID», включив режим разработчика в Discord). В `config.example.json` только плейсхолдеры (`ID_СЕРВЕРА`, `ID_ПОЛЬЗОВАТЕЛЯ_1` и т.д.) -- реальных id сервера и людей в шаблоне нет
4. **После любой правки `config.json` бота надо перезапустить**: id каналов/ролей читаются один раз при старте, и старый id останется в памяти (именно поэтому перенос глухого падал с `Could not resolve channel to a guild voice channel`, когда в конфиге уже был новый канал). Битые id бот теперь проверяет при старте и пишет: `[config] channel_common = ...: канала нет -- исправь config.json и ПЕРЕЗАПУСТИ бота`
5. **Интенты.** Привилегированный **Message Content** нужен двум вещам: пересылке из `pipe_channel_source` и текстовым командам `panda ...`. В портале приложения он включён (заявку подавать не надо, пока приложение в < 100 серверах), и код его запрашивает. Если Discord его отзовёт или в `config.json` стоит `"MESSAGE_CONTENT": false` -- бот всё равно запустится, только без пересылки и без команд `panda ...` (напишет об этом в лог). **GuildMembers** по-прежнему НЕ используется: вход/выход участников ловятся REST-поллингом. Из привилегий дополнительно ничего включать не нужно; из непривилегированных используется **GuildModeration** -- он даёт журнал аудита для авторства действий (`кто замутил/перенёс`)

Зависимости уже стоят (`node_modules` в комплекте). Для чистой установки: `npm install` (+ вручную докачать бинарник yt-dlp: `node node_modules/youtube-dl-exec/dist/install.js`, и `@discordjs/opus` — prebuild).

## Что умеет

- **Профильный статус бота:** виден везде, даже вне голосового. Играет музыку -- `Слушает: 🎶 Трек — «Канал»` (на паузе `⏸`), сидит без музыки -- `Смотрит: 🎧 «Канал»`, свободен -- `Играет: /help · /play · /join`. Обновлений не больше одного в 5 сек (лимит Discord на presence), текст берётся актуальный, повтор того же статуса не отправляется
- **Статус голосового канала:** пока бот сидит в канале, он пишет в его шапке, что играет (`🎶 Трек — 3:45`, на паузе `⏸`), сколько треков в очереди, сколько людей в комнате и сколько он там (`⏱ бот тут: 12 мин`). Обновляется по событиям (смена трека, очередь, вход/выход людей) и раз в минуту для счётчика времени; при выходе и при переезде в другой канал статус снимается с прежнего. Запросы к API склеиваются дебаунсом (не чаще раза в 3 сек), в лог идут только ошибки
- **Владельцы каналов:** создав голосовой канал и получив права, участник становится владельцем: бот выдаёт ему SPEAK/MUTE/DEAF/MOVE, ставит тег 🔑 перед ником (и снимает, когда прав не остаётся; сверка догоняет теги после рестарта бота). Роли ADM/MOD (`role_admin`/`role_moder`) -- исключение: ключа у них не бывает (права есть всегда и все свои это знают), самодрисованный бот удаляет
- **Мут/глухота:** мут в чужом канале → оверрайд SPEAK:false + ЛС-уведомление + журнал; жалоба в общем канале → авто-размут; глухота в чужом канале → CONNECT:false + перенос в общий канал
- **Бан-таймаут:** выход с сервера → таймаут 20 мин (настраивается `onLeaveBanTimeout`); перезаход в течение таймаута → ЛС-предупреждение + бан до конца срока; разбан автоматический, переживает рестарт бота (SQLite)
- **Музыка:** `/play` (ссылка/поиск/плейлист), `/join` (зайти в канал и остаться там, музыка не нужна -- удобно «посидеть с ботом»), `/skip`, `/stop`, `/pause`, `/resume`, `/queue`, `/leave` (плюс `/help`). Сам бот не уходит: кончилась песня или `/stop` -- он остаётся в канале, пока не позовёшь в другую комнату или не скажешь `/leave` (заход и выход видны в логе: `[music] подключился к ...` / `[music] вышел из ...`). Права: админ, модер или роль DJ (`role_dj`). YouTube ходит через прокси `MUSIC_PROXY` (socks5), если прокси не отвечает 3 секунды — напрямую (DIRECT)
- **Мост серверов (pipe):** сообщение человека в `pipe_channel_source` (пандалогия) пересылается в `pipe_channel_target` (общий чат) **от имени бота**, затем оригинал удаляется. Пересылается и текст, и **вложения** (картинки/файлы): раньше объекты вложений передавались в Discord как есть и терялись, из-за чего на сообщение-картинку бот отвечал `50006 Cannot send an empty message` -- теперь вложения передаются ссылкой, а файл без текста пересылается как файл. Порядок именно такой (сперва отправка, потом удаление) -- при ошибке отправки сообщение остаётся в источнике, а не пропадает. Требует интента **Message Content**: без него Discord присылает событие с пустым текстом, и бот ничего не пересылает и ничего не удаляет (в логе: `[pipe] ... НЕ переслано`)
- **Инструкция (`/help` и `panda help`):** тот же текст, что приходит в стартовой ЛС. `/help` — слэш-команда, доступна всем и сразу (без DJ-роли и без голосового канала), ответ виден только вызвавшему; `panda help` — бот присылает её в ЛС (сама команда из канала убирается). Один источник текста на все три входа — `/help`, `panda help` и стартовая ЛС
- **Команды в чате:** `panda ping`, `panda help`, `panda file`, `panda test`, `panda dm @user текст` (админам). `panda dm` принимает и упоминание, и просто id (`panda dm 123456789012345678 текст`); команду бот удаляет **только после успешной отправки**, а если ЛС не ушло -- пишет причину в канал и в лог (раньше в этом случае была полная тишина, а команда всё равно удалялась). `panda test` -- самопроверка: бот пишет ЛС тому, кто её вызвал (никаких зашитых id в коде нет)
- **При старте** бот шлёт ЛС с инструкцией списку людей из `STARTUP_DM`; первый id из этого списка используется в тексте помощи как «владелец» -- так в коде нет ни одного зашитого id, и репозиторий можно отдавать людям
- **Лог (окно бота) -- только события**, без периодического шума: вход/выход/переход по голосовым каналам, микрофон/наушники/стрим/камера, создание и удаление каналов, музыка (`[music] играю: ...`), слэш-команды и `panda ...` (`[cmd]`). Если в конфиге битый id -- при старте будет строка `[config] ...`; если не удался перенос глухого участника -- `[voice] перенос ...`. Остальное молчит. У мутов/глухоты/переносов указывается ещё и **автор** (`кто: ...`): Discord не присылает его в голосовых событиях, поэтому он берётся из журнала аудита (интент **GuildModeration** -- НЕ привилегированный, одобрения не требует; нужен право «Просматривать журнал аудита», при приглашении с `permissions=8` оно есть).

## Git

`config.json`, базы и зависимости уже в `.gitignore`. Начало работы:

```bash
git init
git add .
git commit -m "PANDAMIA bot v2.2.3"
```

**Процесс обновлений:** изменения готовит Codebuff и **сам оформляет коммит**;
владелец смотрит `git log` / `git show` -- и **push делает сам** (`git push`).
Так в репозитории всегда лежит восстановимая история: любой коммит можно
откатить (`git revert`) или достать файл из прошлого (`git checkout <hash> -- путь/к/файлу`).
Токен и базы в git не попадают (см. `.gitignore`).
